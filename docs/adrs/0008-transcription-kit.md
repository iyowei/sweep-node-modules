# ADR 0008: 转写契约套件

> **状态**: 已接受 (Accepted)
> **日期**: 2026-09-23
> **决策者**: 沈委
> **标签**: [工程]
> **影响范围**: [全项目]

## 上下文与问题陈述 (Context & Problem)

本项目当前为 TypeScript 参考实现; 未来可能以 Rust / C 等语言重写 (性能或分发需求)。多语言并存的最大风险不是「写不出」, 而是**等价性无据**: 没有语言中立的契约与机械验收, 每次转写都退化为「看着 TS 重抄一遍」, 行为漂移无法察觉。

## 被放弃的替代方案 (Options Considered & Rejected)

**[只写提示词, 不做程序化验收]**

放弃理由: 提示词是纪律不是规格; 没有确定性验收器兜底, 「照契约实现」无法判定真伪, 漂移只能靠人工通读。

**[不立契约, 直接以 TS 源码为转写依据]**

放弃理由: 源码是实现的投影, 不是规则的投影; 以实现为准会把实现的历史包袱一并固化 (违背「忠于规则不忠于实现」)。

**[契约只写文字, 不做金样本]**

放弃理由: 文字契约无法机械验收; 金样本语料是「期望值可推演辩护」的可执行形态, 是防漂移的物理闸门。

**[把语料或验收器做成第三方依赖]**

放弃理由: 套件自身必须零依赖、可脱机运行 (与 [ADR 0003](0003-zero-runtime-deps.md) 同源), 否则转写方被工具链绑架。

## 决策结论与选择原因 (Decision & Why)

1. **七件套结构** (`docs/protocol/` + `scripts/transcription/`): 编号行为契约 (BC / OF / EC) + 语料 schema + 金样本语料 + 覆盖表 + 确定性验收器 + 变异生成器 + 实施提示词。
2. **黑盒优先**: 验收接口 = argv / env / stdin → stdout / stderr / 退出码 / 文件系统终态; 任何语言的实现经同一语料验收 (各语言的模块边界不进验收口径)。
3. **语料纪律**: 期望必须能由条款 + fixture 尺寸**推演辩护**, 严禁「跑一遍记下来」式捕获; 语料只增不改既有期望, 改期望须过三向定责 (修语料 / 修契约 / 修实现) 并写明依据。
4. **变异自证**: 验收器必须能抓住注入缺陷的 mutant, 抓不住的语料不算数。
5. **提示词只背纪律**: 规格全量在契约与语料; 提示词承载「实施者角色 / 未覆盖处停手报缺口 / 只许等价不许更优 / conformance 全绿才算完」, 不含规格本体。

选择原因: 等价性从「人工通读」变为「机械验收」; 契约与语料以设计文档为权威出处, 三者同批演进, 漂移即红。

## 后果与权衡妥协 (Consequences & Trade-offs)

**正面收益**

- 未来任意语言重写有机械验收路径; 行为契约本身成为实现的第二重自我描述, 与真实实现互为照妖镜;
- 变异自证持续反检语料盲区。

**权衡妥协**

- 行为变更的维护成本上升为「三处一致」(设计文档 / 契约条款 / 语料), 由影响面扫描与既有闸门兜住;
- 体积数字语料依赖文件系统块口径, 跨平台复跑需重校准 (已登记为已知风险)。

## 验证方式与关联引用 (Validation & References)

**验证口径 (落地核验)**

1. TS 参考实现过金样本 40/40 (bun 与 node 双载体, 三连跑逐字节一致);
2. 变异自证 6/6 (覆盖表见 `docs/protocol/conformance/coverage.md`);
3. 不可黑盒条款 8 条显式豁免并写明理由。
