# 转写实施纪律 (语言无关)

> 用途: 把一套既有实现按「行为契约 + 输出规格 + 边界与错误语义表 + 全量金样本语料 + 验收器」
> 转写到目标语言时, 约束实施者 (AI 或人) 的行为。
> 本文件不承载任何规格: 规格全量在契约与语料中 (输入包自足)。本文件只回答「怎么实施」。

## 一、角色

你是实施者, 不是设计者, 不是优化者。

- 逐条实现契约条款; 行为面一切以契约为准。
- 「更合理 / 更优雅 / 更高效」的改动, 只要改变可观察行为, 一律不做。
- 可观察行为面 = argv / env / stdin / cwd → stdout / stderr / 退出码 / 文件系统效果。
  「等价」= 该面上与参考实现逐字节一致。实现风格 (模块划分 / 类型系统 / 语言习惯) 不作要求,
  也不构成偏离契约的借口。

## 二、硬纪律

1. **逐条实施并回填映射表**: 每条契约条款 (如 BC-* / OF-* / EC-*) 对应到目标语言的代码位置。
   交付的完成定义不是「写完」, 而是「映射表无空行 + 验收器全绿」。
2. **规格未覆盖处停手报缺口, 不发明**: 契约没写、语料没覆盖、而实现必须做决定的地方,
   记入缺口清单 (位置 + 疑问 + 关联条款), 继续其余部分; 严禁猜测、严禁静默替换、严禁把
   「参考实现碰巧这么做」当规格 (参考实现的偶然行为不是契约, 除非条款能为其辩护)。
3. **只许等价, 不许附加**: 不添加契约之外的 stdout / stderr 输出 (额外提示语、日志、进度),
   不额外读写文件, 不改退出码语义, 不「顺便」多删 / 少删一个字节。
4. **不动套件件**: 契约 / 输出规格 / 边界表 / 语料 / 验收器一律只读。发现它们互相矛盾或存在
   缺漏 (如语料与契约冲突), 报缺口等裁决, 不得擅改任何一件。
5. **完成判据以验收器为准**: 自跑验收器 (conformance), 全绿 (含连跑三次结果一致) 才算完成。
   未全绿不得声称完成, 也不得「先交付再修」。
6. **失败先定责, 依据是契约原文**: 验收失败时先判是实现缺陷 / 契约缺漏 / 语料错误。
   确认实现缺陷就改实现; 确认套件侧问题就报缺口等裁决。严禁改语料迁就实现 (那是把验收器
   变成永远绿的装饰)。
7. **环境相关路径如实实施**: 降级路径 (无 TTY / NO_COLOR / 平台差异 / 外部命令缺失) 按契约
   与边界表实现, 不得因「本机跑不到」而省略。黑盒验收面上做得到的事, 没有「以后再说」。

## 三、产出格式 (交付物三件, 缺一不可)

1. **条款 → 代码位置映射表**: 每条契约条款一行, 指向目标代码 (文件与行号, 或函数名);
   未实施 / 存疑的条款显式标注, 不静默漏。
2. **缺口清单**: 每条含位置、疑问、关联条款、影响面; 无缺口也要显式声明「无」。
3. **验收报告原文**: 运行命令 + 完整输出 (含失败明细)。严禁摘要代原文、严禁「差不多都过」。
