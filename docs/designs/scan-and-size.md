## 扫描算法

1. 自每个根递归遍历; 目录名恰为 `node_modules` 时记录其父目录为「项目」, 并**不再下钻** (嵌套天然解决);
2. 符号链接目录不跟进 (防环、防误出根);
3. 排除判定在进入目录时进行: 路径段命中 `exclude` 即整棵子树跳过;
4. 多根结果合并, 按 realpath 去重;
5. 跳过 `.git` 目录 (不可能含项目依赖, 直接减掉整棵子树的遍历开销)。

## 体积统计 (候选, 待试验场基准裁定)

平台命令 (`du`) 是 POSIX 专属, 与 [ADR 0007](../adrs/0007-platform-portability.md)「核心零 POSIX 假设」冲突, 只允许作为可用时的快路径; 最终取舍在试验场基准于两候选间裁定, 裁定后回写本节:

- **候选 A (双轨)**: unix (macOS / Linux) 有 `du` 走批量单次快路径, Windows 走纯实现基线;
- **候选 B (统一)**: 全平台统一纯实现 (递归统计), 单一代码路径、行为可预测。

共同要求: 统计不得跟随符号链接 (与扫描同策); 不得逐处 spawn 或逐处独立遍历。

## 性能要点 (热路径 = 目录遍历, 性能不能差)

- `readdir withFileTypes` 取条目类型, 免逐个 `lstat`;
- 命中 `node_modules` 即剪枝, 不下钻;
- 跳过 `.git` 目录;
- 符号链接目录不跟进;
- 体积统计批量或单遍完成, 不逐处 spawn (候选见「体积统计」节)。

## 错误与边界

| 场景       | 处置               |
| ---------- | ------------------ |
| 目录不可读 | 警告并跳过, 不中断 |
| 某根不存在 | 警告并跳过该根     |
